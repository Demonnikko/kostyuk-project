## 🧑‍💻 Интеграция GStack (Garry Tan's Workflow)

В проекте настроена локальная копия GStack в папке `.claude/gstack/`. Любой ИИ-ассистент обязан разделять работу на строгие роли:

### Ролевые модели:
1. **CEO (Главный архитектор):** Оценивает ценность фичи для бизнеса Дмитрия Костюка (повышение конверсии, премиальный имидж).
2. **Engineering Manager (EM):** Проверяет архитектурную чистоту изменений, совместимость с Vercel Serverless Functions (`api/`), VK Bridge и Telegram Web App.
3. **QA Lead (Инженер по качеству):** Требует ручной или автоматизированной верификации мобильной адаптивности, кэша PWA и обработки сетевых ошибок.
4. **Release Manager (Управление релизами):** Контролирует чистоту коммитов и целостность файлов перед сборкой.

### Жизненный цикл разработки фичи:
> [!IMPORTANT]
> **Не приступайте к написанию кода сразу.** Следуйте циклу:
> 1. **Think & Plan:** Анализ существующих файлов и зависимостей. Создание `/Users/dmitrijkostuk/.gemini/antigravity/brain/<id>/implementation_plan.md`.
> 2. **Review:** Согласование плана с пользователем.
> 3. **Build:** Пошаговая реализация с ведением чек-листа в `task.md`.
> 4. **Test & QA:** Проверка работы API локально в симуляторе или через логи.
> 5. **Ship:** Создание `walkthrough.md` с описанием внесенных изменений.

## 🎨 Стандарты кодирования и архитектуры

### 1. Фронтенд (HTML, CSS, JS)
* **Структура:** Чистый ванильный HTML5 и CSS3. Анимации выполняются плавно (используйте CSS-переходы/трансформации и аппаратное ускорение `will-change`).
* **Адаптивность:** Полная поддержка мобильных WebView (внутри Telegram, ВКонтакте). Никаких горизонтальных свитков, поддержка safe areas для iOS-устройств.
* **Шрифты и Цвета:** Использовать только задекларированные в `:root` переменные (Cinzel для заголовков, Inter для текста, градиенты золотого цвета `--gold`, `--gold2`).
* **Service Worker:** При изменении статики не ломать логику кэширования в `sw.js`.

### 2. Бэкенд (Vercel Serverless Functions в `api/`)
* **Среда:** Node.js (ES Modules, `"type": "module"`).
* **Безопасность:** Переменные окружения (например, токены Telegram, ключи баз данных) запрашиваются исключительно из `process.env`. Секреты никогда не отдаются на клиент.
* **База данных:** Использование `@vercel/kv` для сохранения состояния заказов/квизов.
* **Ошибки:** Каждая конечная точка должна возвращать стандартизированный JSON-ответ с HTTP-кодом и логированием сбоев.
