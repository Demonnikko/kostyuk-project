## 1. ЧТО ЭТО ЗА ПРОЕКТ

**KOSTYUK PROJECT** — экосистема из хаба и трёх направлений иллюзиониста Дмитрия Костюка (Ярославль).

| Раздел | Папка | Что это |
|---|---|---|
| **Хаб** | `index.html` + `hub.css` | Главная. Разводит на 3 направления. |
| **Авторские шоу** | `concerts/` | 3 шоу: `secret/`, `huligan/`, `matvey/`. Продажа билетов с выбором места. |
| **Частные события** | `events/` | Иллюзионист на свадьбу/корпоратив/юбилей. Заявка + расчёт. |
| **Школа фокусов** | `school/` | ABRACADABRA — обучение детей 7–13 лет. Заявка. |

**Единый слой:** `ecosystem.css` (палитра, шапка, подвал, типографика) + `ecosystem.js` (строит шапку, переключатель «Все проекты», подвал, кнопку Telegram на всех страницах).

**Правило перелинковки:** на КАЖDOЙ странице в шапке и подвале должны быть ссылки на два других направления. Это уже сделано через `ecosystem.js` — не ломать.

Планка: сайт должен выглядеть как у топовых билетных агрегаторов, не как самоделка.

**Палитра (только эти значения, из `ecosystem.css :root`):**
- Фон: `#030303` · Поверхности: `#0a0a0c`, `#111114`

**Шрифты:** заголовки — Cinzel, текст — Inter. Других не вводить.

**Единые правила (действуют на всех разделах):**

- Заголовки h1 ~79px десктоп / 40px мобайл, вес 700. h2 — 44px. Единая шкала.

**Мобильная адаптивность обязательна:** никаких горизонтальных скроллов, поддержка safe-area (iOS). Проверять на 375px И на 1440px — сайт должен быть хорош на ОБОИХ, не только на телефоне.

## 3. ПОКУПКА БИЛЕТОВ — СЕРДЦЕ ПРОЕКТА

Воронка (шоу `secret` и `huligan`): **дата → выбор места на схеме зала → контакты → оплата → билет**.
`matvey` — упрощённая схема (заявка, «менеджер свяжется»).

Стандарт качества — как у Кассир.ру / Яндекс.Афиши:
- Выбор места визуально понятен, промахнуться по месту нельзя (у мест увеличенная зона клика).
- Если дата одна — она выбрана автоматически, лишних кликов нет.
- После оплаты пользователь СРАЗУ видит свой билет (кнопка «Открыть билет» тянет ссылку из `/api/ticket-link`). Никаких «придёт на контакты» — ботов нет.
- Цена видна заранее, не прячется до последнего шага.

**Оплата:** только **T‑Pay (Tinkoff/Т‑Банк эквайринг)**. Переменные `TBANK_*` в окружении Vercel.
⚠️ **Эквайринг ещё НЕ подключён — это нормально, будет позже. Не считать за баг, не пытаться чинить оплату.** Работаем над всем остальным.

**Боты Telegram/VK убраны.** Всё — через сайт. Если видишь код/тексты, завязанные на ботов, — это устаревшее, чистить.

## 4. АДМИНКА (`admin/index.html`)

Вход по паролю. Пароль хранится в **Firebase** (`ticket_admin/adminPassword`), НЕ в коде и НЕ в env. Сброс — через консоль Firebase.

Админка — центр контроля. Должна давать полную картину по каждому покупателю:
- Список всех броней/билетов по всем 3 шоу, статусы (бронь / оплачен / отменён / возврат).
- Кто купил, контакты, какие места, сумма, дата покупки.
- **Путь пользователя:** откуда пришёл (источник), когда и на каком шаге был.
- Кнопки управления: подтвердить, **отменить**, **оформить возврат** (освобождает место обратно).
- Настройки шоу: дата, время, площадка, цены по зонам.

Цель: если что-то пошло не так — админ видит где именно и может вернуть билет.

## 5. ТЕХНИКА

- **Стек:** ванильный HTML/CSS/JS. Бэкенд — Vercel Serverless (`api/`, ES Modules). Данные — Firebase + `@vercel/kv`.
- **Запуск локально для проверки:** `python3 -m http.server 8899` из корня (статика + вёрстка; API не работает локально без `vercel dev`). Открывать `http://localhost:8899/`.
- **Секреты** только из `process.env`, на клиент не отдавать.
- **Service Worker** (`sw.js`): при изменении статики не ломать кэш — бампать версию.
- **Кэш CSS/JS:** при правке общих файлов повышать `?v=N` в ссылках на всех страницах, иначе браузер отдаёт старое.
- **Деплой не трогать без явной просьбы.** Все правки локальные, пока не сказано «выкатывай».
