## 6. PRODAMUS — ПЛАН ГОТОВ (код НЕ писали) — детали в памяти `prodamus-integration-plan.md`

**Модель: РАЗОВАЯ оплата брони, НЕ подписка.** Исключено: subscription/recurring/expires_at/paywall/Pro-доступ/MIN_AMOUNT/SaaS.
Ориентир — существующий T-Bank код (book.js/huligan.js), адаптируем платёжный слой под Prodamus.

**Подтверждено офиц. докой Prodamus:** вебхук multipart/form-data (callbackType=json НЕ используем — подпись для JSON не подтверждена). Подпись в заголовке `Sign`, HMAC-SHA256 (сортировка ключей + экранирование `/`). Ответ 200+'success'. payment_status: success/Order_canceled/Order_denied. `order_num`=НАШ id, `order_id`=id Prodamus. Параметры ссылки: link_expired, payments_limit=1, sys (согласовать с поддержкой), _param_xxx. API проверки статуса (GetState) НЕТ → статус только по Firebase-броне от вебхука.

**Финальные решения (v5):**
1. `order_num = bookingId + '-' + paymentAttemptId` — каждая попытка = уник. номер (изоляция: старый вебхук отменённой попытки не тронет новую).
2. paymentAttemptId → своя попытка в ticket_bookings/{id}/payments/{attemptId} с expectedAmount (сервер считает через getZonePrices, НЕ пересчитывать после).
3. HOLD во время оплаты: место reserved→payment_pending, paymentHoldUntil = linkExpiredAt + 15мин grace. payments_limit=1.
4. Идемпотентность по order_id Prodamus. Вебхук ДВУХФАЗНО: received→(подтвердить бронь/места)→processed. Помечать processed ТОЛЬКО после подтверждения (падение между → ретрай доработает, не зависнет).
5. paid_conflict — аварийный fallback (success пришёл, но место уже чужое): деньги фиксируем, админ разбирает (возврат/др.место), место не отбираем.
6. urlSuccess — только UX. Истина = подписанный webhook. get_status читает Firebase.

**Схема места:** free → reserved(10м) → payment_pending(link_expired+15м) → taken. Ветки →free (TTL/cancel/denied/expired), →paid_conflict. Все переходы через ETag.

**Файлы (создать):** api/_endpoints/prodamus.js (init/notify/get_status), shared/prodamus-sign.js (подпись+тест), shared/payment-events.js (журнал+идемпотентность received/processed).
**(изменить):** api/[endpoint].js (роут), api/_endpoints/seats.js (+статус payment_pending), concerts/secret+huligan/index.html (init+get_status).
**НЕ трогать:** clientKey/bookingId/билеты, Матвей, резерв-ETag ядро.
**env:** PRODAMUS_SECRET_KEY, PRODAMUS_FORM_URL, PRODAMUS_SYS.
**Перед кодом:** согласовать sys с поддержкой Prodamus + 1 тестовый платёж (снять реальный payload: bookingId в order_num, currency, формат sum, возврат _param).
**Skill установлен глобально:** `prodamus-subscription` (~/.claude/skills/) — но он про подписки, применима только логика вебхука.

**ГЛАВНЫЙ ВОПРОС (заказчик спрашивал): могут ли 2 человека оплатить одно место? → НЕТ.** HOLD при выборе (до оплаты) + ETag + payment_pending до link_expired+grace. Второй на занятое место → 409, не создаст бронь.
